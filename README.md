# AI Popup Scouter — 퍼스트 웨이브

브랜드명 목록 없이 **상품군 + 소비자 후기 검색어**로 네이버 블로그를 검색하고, 실제 자료에 등장한 이름과 근거를 추출하는 독립 실험입니다. Python 3.11 이상이며 외부 패키지 설치는 필요 없습니다.

**뉴스는 발굴 경로에서 제외했습니다.** Google 뉴스 RSS, 네이버 뉴스, 인증정보가 없을 때 뉴스로 대체하는 동작을 제거했습니다. 기존 뉴스 기반 실행 예시도 현재 결과에서 제거했습니다. 과거 뉴스 JSON을 오프라인으로 넣어도 분석에 포함하지 않습니다.

## Codespaces에서 실행

1. 이 저장소의 **Code → Codespaces → Create codespace on main**을 엽니다. 이미 사용 중이면 터미널에서 `git pull`로 갱신합니다.
2. 네이버 개발자센터에서 검색 API를 사용하는 앱을 준비합니다.
3. GitHub 개인 설정의 **Codespaces secrets**에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 등록하고 이 저장소에서 사용할 수 있도록 허용합니다. 기존 Codespace는 비밀 설정이 반영되도록 재시작합니다. 키는 코드·채팅에 붙여넣지 않습니다.
4. 터미널에서 실행합니다.

```bash
python discover.py --topic 식품 --source naver
```

상품군은 고정 목록이 아닙니다. 여러 상품군을 지정할 수도 있습니다.

```bash
python discover.py --topic 패션 --topic 생활용품 --per-query 1000 --max-documents 6000
```

**네이버 키 없이 실시간 검색을 실행할 수는 없습니다.** 인증이 없으면 설명과 함께 중단하며 다른 출처로 대체하지 않습니다. `--source google`은 더 이상 지원하지 않습니다.

공식 API 문서: https://developers.naver.com/docs/serviceapi/search/blog/blog.md

## 수집 범위

- 상품군당 검색어 6개: 직접 구매 후기, 재구매 후기, 예약 구매 후기, 작은 가게 방문 후기, 로컬마켓 구매 후기, 독립 브랜드 사용 후기.
- 기본 검색어당 최대 500개, 페이지당 최대 100개를 순차 수집합니다.
- 검색어당 설정 상한은 1,000개입니다. 네이버 검색 API가 접근 가능한 결과 범위를 넘기지 않습니다.
- 기본 중복 제거 후 분석 상한은 3,000문서입니다. `--max-documents`로 최대 20,000개까지 지정할 수 있습니다.
- 예: 상품군 하나는 6검색어 × 500개 = 최대 3,000개 검색 결과를 요청하지만, 검색 중복·실제 결과 부족·기간 필터·오류로 고유 확보 문서는 더 적을 수 있습니다.
- 최대 검색어 60개, 동시 검색어 3개입니다. 실행 규모에 따라 API 호출량과 AI 비용이 증가합니다.
- 두 번째 이후 페이지에서 실패해도 앞서 확보한 페이지는 보존합니다. 반복 페이지는 중복 집계하지 않습니다.
- 검색 API의 `total`은 페이지 종료 판단에만 사용하며 브랜드 언급량으로 사용하지 않습니다.
- `--days`는 받은 결과에 대한 날짜 필터입니다. API에서 해당 기간 전체를 확보한다는 의미가 아닙니다.

검색어를 직접 추가할 수 있습니다.

```bash
python discover.py --topic 생활용품 --query '독립 디자인 제품 사용 후기' --days 30
```

## 결과 확인

- `runs/latest/report.html`: 다운로드해서 브라우저로 여는 보고서
- `runs/latest/report.json`: 후보·근거·오류·검색별 수집 진행 정보
- `runs/latest/documents.json`: 실제 확보한 제목·요약·게시일·URL
- `state/discovery.sqlite`: 이름의 최초 발견 시각과 관련 문서 ID

`report.json`의 `collection_stats`에는 검색어별 요청량·확보량·페이지 요청 횟수·중단 이유가 표시됩니다. `document_cap_reached`로 분석 상한 적용 여부를 확인할 수 있습니다. 실패가 있거나 분석할 문서가 없으면 비정상 종료 코드 2를 반환하되, 확보한 결과와 오류는 보고서에 남깁니다. 인증정보 누락은 수집 전에 중단합니다.

원문 전체가 아닌 검색 제목·요약만 읽습니다. 같은 URL은 통합하지만 다른 URL로 복제된 글은 자동 통합하지 않습니다. 같은 글을 여러 번 검색해도 문서 수를 부풀리지 않습니다. 원본 전체를 DB에 계속 누적하지 않으며, `runs/`의 과거 실행 폴더는 필요할 때 삭제할 수 있습니다.

## AI 이름 추출

기본 `--extractor rule`은 명시적인 ‘브랜드 “이름”’ 등에서 이름을 찾는 규칙 기반 방식입니다. **블로그는 뉴스와 문체가 달라 이 방식의 누락이 많을 수 있으며 추천 품질은 검증되지 않았습니다.** AI 추출에는 실행환경 비밀 설정에 별도의 `OPENAI_API_KEY`가 필요합니다.

```bash
python discover.py --topic 패션 --extractor openai --model gpt-4.1-mini
```

제목·요약을 OpenAI API로 보내므로 비용이 발생합니다. AI가 돌려준 이름이 인용에 있고 인용이 제공된 원문에 그대로 존재하는지 코드로 검증합니다. 검증되지 않은 추출은 버립니다. AI 오류를 규칙 추출 성공으로 대체하지 않습니다.

## 한계

- 블로그라는 이유만으로 자발적 소비자 후기라고 판단하지 않습니다. 협찬·광고·판매자 작성과 중복 작성자는 후속 검증 대상입니다.
- 뉴스 수집 제거는 추천 품질 개선을 보장하지 않습니다. 새 경로의 실수집·후보 적합성 검증이 필요합니다.
- 처음 발견한 이름은 신생·급성장 브랜드라는 뜻이 아닙니다. 대형 브랜드·기존 팝업 이력 검증은 아직 완료하지 않았습니다.
- 원문에 나타난 백화점·팝업 언급은 검토 표시만 하며 해당 브랜드의 이력으로 단정하지 않습니다.
- 문서 수는 확보한 검색 표본의 근거 수이며 전체 시장 언급량·성장 순위가 아닙니다.
- 이름 표기 정규화만 하므로 동명이인·동명 가게를 사람이 확인해야 합니다.
- 인스타·쇼츠·마켓 참가 목록과 상시 예약 실행은 아직 연결하지 않았습니다.
