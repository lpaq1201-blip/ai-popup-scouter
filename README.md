# AI Popup Scouter — 퍼스트 웨이브

브랜드명 목록 없이 **상품군 + 발견 신호**로 검색하고, 결과에 실제로 적힌 브랜드·가게 이름과 인용 근거를 추출합니다. 기존 novel 저장소와 사이트는 수정하지 않습니다. Python 3.11 이상, 외부 패키지 설치 없이 실행합니다.

## 실제 실행 결과

- [실행 검증 기록](VALIDATION.md)
- [실제 수집 후보와 근거 JSON](examples/live-2026-11-12/report.json)
- [실제 확보 문서](examples/live-2026-11-12/documents.json)
- [HTML 보고서 파일](examples/live-2026-11-12/report.html): 다운로드 후 브라우저에서 열기

식품·뷰티는 실행 예시일 뿐 고정 상품군이 아닙니다. 이 결과는 뉴스 제목·요약에서 추출한 이름 후보이며 상승 브랜드 추천이 아닙니다.

## 실행

```bash
python discover.py --topic 식품 --topic 뷰티 --source google
```

상품군은 고정 목록이 아닙니다. `--topic`을 바꾸거나 여러 번 지정할 수 있습니다. 상품군 없이 실행하면 일반 브랜드 발굴 검색을 합니다. 브랜드명을 넣는 프로그램이 아닙니다.

```bash
python discover.py --topic 생활용품 --query '독립 디자인 브랜드 신규 입점' --days 30
```

- `runs/latest/report.html`: 인터넷 연결 없이 열 수 있는 결과 보고서
- `runs/latest/report.json`: API 연결에 사용할 구조화 결과, 오류·범위 포함
- `runs/latest/documents.json`: 실제 확보한 제목·요약·게시일·URL, 재현용
- `state/discovery.sqlite`: 정규화한 이름과 최초 발견 시각, 문서 ID. 원본 전체 게시물은 DB에 누적하지 않음

`runs/`의 과거 실행 폴더는 필요할 때 삭제할 수 있습니다. 재검색 시 후보 레지스트리의 최초 발견 시각은 유지됩니다. 이름 표기만 정규화하므로 동명이인·동명 가게는 검토 대상이며, 의미상 별칭 자동 통합은 하지 않습니다.

## 네이버 검색 연결

네이버 개발자센터에서 검색 API 사용 권한을 가진 앱을 만들고, 실행환경의 비밀 설정에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 등록합니다. 키를 채팅·코드·명령행 인자로 보내지 않습니다.

```bash
python discover.py --topic 패션 --source naver --per-query 50
```

블로그·뉴스 검색을 날짜순으로 조회합니다. 쿼리당 채널별 최대 100개, 첫 페이지까지 구현했습니다. **대량 페이지네이션과 상시 모니터링은 이번 구현에 포함하지 않았습니다.** 검색 API의 total은 언급량으로 사용하지 않습니다. `auto`는 두 네이버 키가 모두 있으면 네이버, 없으면 Google 뉴스 RSS를 사용합니다. 네이버가 실패했다고 몰래 다른 출처로 바꾸지 않으며 실패는 보고서에 남깁니다.

공식 참고: https://developers.naver.com/docs/serviceapi/search/blog/blog.md

## AI 이름 추출 연결

실행환경 비밀 설정에 `OPENAI_API_KEY`를 등록한 뒤 명시적으로 실행합니다. 문서 제목·요약이 OpenAI API에 전달되며 API 비용이 발생합니다.

```bash
python discover.py --topic 패션 --extractor openai --model gpt-4.1-mini
```

AI에는 문서에서 실제 등장한 이름과 정확한 인용만 반환하도록 요청합니다. 반환된 이름이 인용에 있고, 인용이 입력 문서에 그대로 존재하며, 문서 ID가 일치하는지 코드로 검증합니다. 검증 실패는 버리고 건수를 기록합니다. 출처 안의 명령은 데이터로 취급하도록 지시합니다. 이 검증은 환각을 줄이지만, 조직/브랜드 분류나 문맥 판단의 정확성을 보장하지 않습니다.

기본 `--extractor rule`은 ‘브랜드 “이름”’ 같은 명시적 패턴을 찾는 보수적인 후보 추출입니다. **AI 분석이 아니며**, 후보를 놓치거나 운영사·기존 대형 브랜드를 포함할 수 있습니다. 자동 추천으로 사용하지 마세요. AI 실패를 규칙 추출 성공으로 대체하지 않습니다.

## 수집 범위·비용 제한

기본: 주제당 발견 검색어 6개, 쿼리당 30문서, 추출 대상 전체 150문서, 동시 요청 3개. 최대 검색어 60개, 추출 문서 2,000개로 실행 범위를 제한합니다. 수집 일부가 실패해도 다른 결과를 보존하며, 오류는 `report.json`에 기록됩니다. 날짜가 없거나 기간 밖인 자료는 최근 자료에 포함하지 않습니다. `--days`는 이미 확보된 결과의 기간 필터이기도 하며 기간 내 전체 검색 결과를 보장하지 않습니다.

Google 뉴스 RSS는 API 키 없이 접근한 공개 피드입니다. 고정 검색 결과 수·과거 범위·서비스 수준을 보장하는 상용 데이터 계약이 아닙니다. 뉴스 중심이므로 초기 소비자 반응을 놓칠 수 있습니다. 제목·요약만 읽으며 기사 본문, 인스타그램, 쇼츠, 네이버 데이터랩을 수집하지 않습니다.

## 이번 결과가 의미하는 것

- ‘확보 문서 수’는 검색에서 가져온 고유 URL 수이며 브랜드 전체 언급량이 아닙니다.
- URL 추적 인자와 같은 링크의 반복 검색은 제거합니다. 서로 다른 URL의 보도자료 재배포·RSS 경유 URL과 원문 URL 중복은 아직 자동 통합하지 않습니다.
- 매체명 수는 소비자 수·독립 작성자 수가 아닙니다. 보도자료가 여러 매체에 실릴 수 있습니다.
- ‘처음 발견’은 우리 레지스트리 기준입니다. 신생 브랜드·급성장·최초 시장 발견을 뜻하지 않습니다.
- AI/규칙 추출은 이름 후보 발굴 단계입니다. 상품군 적합성, 대형/기성 브랜드 제외, 백화점 팝업 이력, 공식 연락처, 생산 역량, 소비자 반응 검증은 후속 단계입니다.
- 보고서는 확보 근거 수순으로 정렬하며 인기·성장 점수를 만들지 않습니다.
- 공개 마켓·입점 목록 수집기는 이번 버전에 아직 연결하지 않았습니다.
